# 验收与审查记录

2026-09-18。范围为单机 Go 原型、第二轮代码审查与五家模型提供商适配。功能测试使用人工示例与本地模型替身；没有调用真实模型，没有做性能压测。

## 验收方式

```sh
go test -race ./...
go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o bin/asteria ./cmd/asteria
```

以上检查均通过，工具链为 Go 1.27.1。按 README 实际回放了初始化两个库、录入、跨库查询，并完成修订、精确审核、历史读取、重建和导出。CLI、HTTP 和 stdio MCP 返回相同证据；实际 HTTP 进程拒绝 Agent 审批并正常退出，旧快照仍可读取。Streamable HTTP MCP 另有实际协议往返测试。

## 第二轮审查与收缩

从使用者角度检查保存、合并、迁移和审核；从维护者角度检查权限入口、状态保留、重复代码和文档承诺。发现的问题均补充了回归验证：

- Markdown 编解码曾移除缩进与行尾空格，可能改变代码块。现在只规范化首尾换行，并按将要保存的正文校验行号，见 [Markdown 测试](../internal/knowledge/markdown_test.go)与[审查回归](../internal/core/review_test.go)。
- 合并曾重新构造条目，丢失原证据、入口与洞察来源类型。现在保留已有元数据，只替换明确变更的内容，见审查回归。
- 历史列表和间接证据追溯使用了不同的权限判断。现在共用当前授权规则；移动到权限外的条目不再出现在历史中，见审查回归。
- 提案版本正确仍可能因序列化规则变化而提交不同正文。现在发布前核对实际前后文件与已展示差异；不一致时拒绝并要求重新提案，见审查回归。
- Agent 移动条目曾被误认为重新验证已有关系。现在允许保留未改变正文与关系的核查记录，同时禁止借旧核查说明修改关系条件，见审查回归。
- 同批新资料与洞察不应误触发待复核；索引等待应可取消；多份 YAML 配置不能被静默截断。相应检查在审查、存储和 CLI 测试中。

整理合并了读取权限与领域过滤，集中正文变动后的复核规则；移除未使用的模型 JSON、搜索及索引读取封装。存储按快照、记录和文件操作拆分，HTTP 直接适配核心方法。没有新增依赖。

文档收敛为 README、系统设计、技术选型和本记录四份；MVP 边界并入系统设计。当前实现与后续云原生候选分开，依赖版本以 go.mod 为准，删除未实测的数字目标和重复伪代码。

## 模型提供商适配

沿用 `core.Model`，维护 OpenRouter、DeepSeek、Qwen、Kimi、GLM 的显式配置，保留 `compatible` 和旧的 URL 配置。未新增依赖，CLI、HTTP 与 MCP 从同一入口创建模型。

[协议测试](../internal/llm/chat_test.go)通过本地 HTTP 服务检查五家的默认端点、鉴权、模型 ID、JSON 模式、输出限制与参数隔离；覆盖 OpenRouter 路由约束、Qwen 非思考参数及 Kimi `max_completion_tokens`。同时检查错误状态不泄露正文、HTTP 200 中的错误信封、截断、拒答、非对象或不符合结构的 JSON、响应体上限、超时与取消。

[配置测试](../internal/llm/config_test.go)检查自定义地址、完整完成接口路径和非法配置；[CLI 测试](../internal/cli/model_test.go)实际经过环境配置、命令、核心导航与 HTTP 适配，确认 `--offline` 忽略无效模型配置。提供商差异依据 README 链接的官方接口说明核对；这不代表已通过真实模型联调。

本轮代码审查修复了 `write` / `revise` 的 context 作用域问题：操作超时此前只传给模型调用，等待提案写锁时会丢失预算。现在同一 context 贯穿后续保存与发布；[预算回归测试](../internal/core/budget_test.go)持有真实文件锁，确认模型返回后仍按操作期限退出，且不保存提案或发布知识。测试已在修复前复现两条路径的失败。

删除了适配器自动剥离 Markdown 代码围栏的修补逻辑，按现有接口约定直接接收 JSON 对象；协议测试覆盖这一行为。没有增加重试、降级或新的防御分支。

## 尚未验证

真实服务的协议兼容性、真实资料的证据命中率、洞察实用性和演化收益，需要真实模型与人工评审。语义去重及被否定关系的跨表述识别仍依赖模型和人工判断。程序校验不证明结论为真。

Docker 环境不可用，镜像构建与 Compose 启动未实测；只完成了 Go 静态构建和配方检查。多机共享写入、生产容量、断电恢复全场景与分布式部署均不在本轮验证范围内。
